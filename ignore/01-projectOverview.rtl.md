# AdaptiveTrader

## OverView

متاتریدر نرم افزاری هست که برای انجام معاملات الگوریتمی استفاده میشه و از زبان MQL5  استفاده میکنه. این نرم افزار امکان وارد کردن محدود کدهای پایتون رو داره ولی به دلایلی ترجیه اینه که تا حد امکان همه ی کدها فقط
به زبان mql5 نوشته بشه. 
.استراتژی: معمولا یک فرمول ریاضی و آماری هستش که به صورت کد در میاد. قواعدی که با اون معامله ها باز و بسته میشن.
روال کار به این صورته که ایده ای به ذهن میرسه و به صورت اندیکاتور متاتریدر کدنویسی میشه.
مرحله اول:
 اندیکاتور یک سری کارهای آماری روی دیتای کندلها انجام میده و چندتا بافر به عنوان خروجی تولید میکنه. این بافرها رو میشه به صورت خطوط روی چارت
نشون داد تا به صورت بصری قابل استفاده بودن و معنادار بودن اونها بررسی بشه. 
مثال شبه کد اندیکاتور:
input int period = 50
input int uperlimit = 85
input int lowelimit = 15
{do some calculation}
خروجی:
buffer0 = [upper qualtile]
buffer1 = [mode]
buffer1 = [lower quantile]

مرحله دوم ، اکسپرت اولیه:
در صورتی که از اندیکاتور راضی باشیم یک اکسپرت اولیه بر پایه اون مینویسیم. این اکسپرت دیتای بافرها و کندل ها رو در اختیار داره.
چندتا سطح تعیین میکنیم و از روی اونها شرط های ورود و خروج رو می نویسیم.
مثال:

input enum position_type = BUY
input int openCondition_price_upperlimit = 1
input int openCondition_price_mode = 0
input int openCondition_price_lowerlimit = -1
input int closeCondition_price_upperlimit = 0
input int closeCondition_price_mode = -1
input int closeCondition_price_lowerlimit = 0

در این اکسپرت عدد 1 به معنی تاثیر مستقیم، عدد 0 به معنی بی تاثیر بودن و عدد -1 به معنی تاثیر معکوس هستش. اکسپرت این اعداد رو از نظر بزرگر و کوچکتر بودن بررسی میکنه و مقادیر بولین کاندیشن ها رو میده:
bool cond_price_upperlimit = last_1m_close > indicator_upperlimit_buffer
اگر تک تک شرط های باز کردن معامله برقرار باشه ، معامله ای در جهت تعیین شده باز میشه و اگر تک تک شرط های بستن معامله برقرار باشه
همه ی معامله های موجود بسته میشن.
این اکسپرت میتونه شرط های دیگه ای هم برای باز و بسته کردن معامله ها داشته باشه.
این اکسپرت مخصوصا برای optimizer داخلی متاتریدر نوشته میشه.

نکته: اپتیمایزر و بک تستر داخلی متاتریدر مطمئن ترین ابزار شبیه سازی استراتژی ها در زمان ها گذشته است و معادلهای پایتونی یا دست نویس هرگز دقت و صحت اون رو ندارن.
نکته: اپتیمایزر داخلی متاتریدر ما رو مجبور میکنه که پارامترهای ورودی رو به صورت دستی انتخاب کنیم، حتی برای بررسی حالت های مختلف باید 
به صورت دستی rang هر متغییر رو مشخص کنیم.
نکته: اپتیمایزر داخلی متاتریدر از روی چند شاخص محدود و مشخص در فضای حالت پارامتر ها جست و جو میکنه. فضای جست و جو چیزی شبیه اینه:

input enum position_type = {BUY,SELL,BOTH}
input int openCondition_price_upperlimit = [-1,0,1]
input int openCondition_price_mode = [-1,0,1]
input int openCondition_price_lowerlimit = [-1,0,1]
input int closeCondition_price_upperlimit = [-1,0,1]
input int closeCondition_price_mode = [-1,0,1]
input int closeCondition_price_lowerlimit = [-1,0,1]

با زیاد شدن پارامترها و حالت های اونها این فضای جست و جو میتونه به سرعت بزرگ بشه.
نکته: خروجی اپتیمایز چیزی شبیه اینه :

score = 1
config_id = 34525
profit_factor = 5.4
max_drawdown = 12%
input enum position_type = BUY
input int openCondition_price_upperlimit = 1
input int openCondition_price_mode = 0
input int openCondition_price_lowerlimit = -1
input int closeCondition_price_upperlimit = 0
input int closeCondition_price_mode = -1
input int closeCondition_price_lowerlimit = 0

برای این اکسپرت در سال 2025 بهترین بازدهی رو داشته. همچنین اطلاعات جانبی دیگه ای هم از عملکرد اسکپرت در اون بازه و با اون تنظیمات میده.
اپتیمایزر یک لیست بلند از انواع کانفیگ ها و نتایج معاملاتی اونها میده که به صورت فایل csv قابل ذخیره اند. هر کدوم رو هم میشه با دوبار 
کلیک کردن به صورت تکی تست کرد و گراف معاملاتی اون رو دید.
نکته: هر اکسپرتی که به اندازه کافی پارامتر قابل تنظیم داشته باشه انعطاف پذیری کافی داره و با اپتیمایزر میشه اون رو به هر بازه زمانی اورفیت کرد. آزمون واقعی اینه که اون کانفیگی که برای مثلا سال 2025 از طریق اپتیمایزر پیدا شده بتونه توی سال 2026 یا 2024 هم عملکرد خوبی داشته باشه. اینطوری مشخص میشه که آیا ما یک edge واقعی پیدا کردیم یا فقط carve_fitting کردیم.
نکته: تقریبا هیچ استراتژی در بلند مدت بازدهی خوبی نداره.
نکته : امکان اپتیمایز داخلی در حین بک تست داده نمیشه.
نکته: فضای کل حالت هایی که یک اکسپرت رو میشه تنظیم کرد به راحتی به میلیونها حالت میرسه. اپتیمایزر در حالت جست و جوس سریع حدود 10 هزار حالت رو برای بازه زمانی خواسته شده بررسی میکنه و بهترین تنظیمات رو به ترتیب نشون میده. اگه فضای پارامترهای ما زیادی به هم نزدیک باشن
اپتیماز به راحتی منجر به اورفیت میشه. اپتیمایزر یک گزینه برای بررسی forward-test هم داره.

مرحله سوم:
بعد از نوشتن اکسپرت و آزمون دستی در دوره های چند هفته ای، چند ماهه، و چند ساله، forward-test  و back-test ممکنه یک استراتژی خوب به نظر بیاد. اینجا ایده اصلی این سیستم تازه شروع میشه.
اکسپرت رو در بازه های کوتاه مدت (مثلا 2 ماه) اپتیمایز میکنیم، مدت کوتاهی (مثلا یک هفته) استفاده میکنیم. و همین کار رو تکرار میکنیم.
متاتریدر امکان اجرای اتومات این سناریو رو نداره. ایده اینه که چون رژیم حاکم بر مارکت همواره در حال تغییر هستش، به جای گشتن بیهوده دنبال استراتژی معجزه آسا و کشف نشده (خنثی نشده) که چندین سال سود ده باشه دنبال چیز دیگری بگردیم. اینکه بتونه در بازه های کوتاه خودش رو با شرایط بازار تطبیق بده و قبل از اینکه بازار خیلی تغییر کنه دوباره اپتیمایز بشه.
برای این کار در یک بازه یک یا چند ساله ، یک پنجره ی خزنده تعریف میکنیم. مثلا مدت بک تست رو 3 ماه در نظر میگیریم و به ازای هر ماه یک بار اپتیمایز کامل انجام میدیم. خروجی رو به صورت CSV ذخیره میکنیم. از هر ماه تعدادی (مثلا 15 تا) کانفیگ برتر رو انتخاب میکنیم و در یک فایل CONFIG_POOL_CSV برای استفاده های آینده ذخیره میکنیم.
نکته: اگه منطق اندیکاتور یا استراتژی نیازمند محاسبات سنگین باشه، اپتیمایزر 10 هزار حالت مختلف بسیار طولانی میشه و عملا امکان تهیه دستی این فایل بسیار سخت و نشدنی میشه.
 یک راه برای افزایش سرعت اپتیمایزر در نظر گرفتم که تست شده و زمان اپتیمایز رو از چندین ساعت به چند دقیقه کاهش میده. روش اینه که از روی اکسپرت اولیه یک اکسپرت مخصوص استخراج کانفیگ های برتر میسازیم. سه تا مود به اکسپرت اضافه میکنیم : 
 input enum MODE{NORMAL,BACKTEST,OPTIMIZE}
 مود نرمال دقیقا مثل اکسپرت اولیه است. 
 مود BACKTEST هیچ معامله ای باز نمیکنه، فقط دیتای کندلها و اندیکاتور رو در اون بازه تست در فایل CSV با اسم مناسب ذخیره میکنه.
 مود OPTIMIZE فضای حالت رو به شکل عادی جست و جو میکنه و معامله هم باز میکنه ولی اندیکاتور لود نمیکنه، تمام اطلاعات لازم رو از روی فایل های CSV مرحله قبل میخونه.

 مرحله چهارم:
 این مرحله یک بازیگر جدید اضافه میشه به نام BACKTESTER . یک نسخه از اکسپرت اولیه هم به صورت کلاس نوشته میشه که ارتباط مستقیم با چارت و اندیکاتورها نداره. اسمش رو TRADER میگذاریم و یک اکسپرت بالادستی هم به اسم manager نوشته میشه. این کلاس کانفیگ ها رو از فایل csv به backtester معرفی میکنه، بازه زمانی رو مشخص میکنه، معیارهای رتبه بندی رو بهش اعلام میکنه، و کلاس تریدر رو هم بهش معرفی میکنه. بک تستر به ازای هر کانفیگ یک نسخه از کلاس تریدر میسازه و دیتایی که لازم داره رو براش تولید میکنه، معامله های صوری براش باز میکنه و عملکردش رو اندازه میگیره و امتیاز میده. در نهایت به تعداد خواسته شده کانفیگ های برتر رو به کلاس منیجر معرفی میکنه. کلاس منیجر تعدادی تریدر با تنظیمات برتر تولید میکنه، یک هفته استفاده میکنه، بعد اونها رو آرشیو میکنه. و این چرخه ادامه پیدا میکنه.

 مرحله پنجم:
 یک اکسپرت اصلی به نام AdaptiveTrader نوشته میشه و به عنوان مدیر اصلی نام برده میشه . اکسپرت manager مرحله قبلی این بار به فرم یک کلاس نوشته میشه. مدیر اصلی تعدادی مدیر میانی تولید میکنه و با اونها به شکل تریدر برخورد میکنه، بین اونها بودجه تقسیم میکنه، سر هر
 هفته ازشون عملکرد میگیره و این طور چیزها. هر مدیر میانی مسئول اجرای یک استراتژی روی یک جفت ارز هستش. مدیر میانی بعد از گرفتن بودجه 
 از فایل کانفیگهای مخصوص به خودش به کمک backtester تعدادی رو انتخاب میکنه و با اونها trader میسازه.
